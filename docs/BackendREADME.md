## 🎯 項目概覽

TON Cat Lottery Backend 是一個基於 Go 的智能抽獎守護進程，專注於自動化監聽和管理 TON Testnet 上的貓咪 NFT 抽獎系統。採用無狀態設計，依賴合約處理所有業務邏輯，後端僅負責自動化觸發抽獎流程。

### 🏗️ **系統架構**

```
┌─────────────────┐    輪詢合約狀態     ┌──────────────────┐
│   後端守護進程    │ ───────────────► │  CatLottery 合約  │
│   (Go Service)  │                   │   (TON Testnet)  │
└─────────────────┘                   └──────────────────┘
        │                                      │
        │ 自動觸發 drawWinner                   │
        │ (使用 W5 錢包私鑰簽名)                 │
        ▼                                      ▼
┌─────────────────┐    自動鑄造 NFT     ┌──────────────────┐
│   TON 區塊鏈     │ ◄─────────────── │   CatNFT 合約     │
│   (交易確認)     │                   │   (NFT 管理)     │
└─────────────────┘                   └──────────────────┘
```

### 🤖 **核心功能**

> **簡化核心**: 後端只做一件事 - 自動化執行 `drawWinner`

#### ✅ **狀態監聽**
- **輪詢機制**: 每 30-60 秒檢查合約 `lotteryActive` 狀態
- **狀態變化檢測**: 監控從 `true` 到 `false` 的轉換
- **參與者驗證**: 確保參與者數量 >= 3 才觸發抽獎
- **緩存優化**: 避免重複 API 調用，減少網路負載

#### ✅ **自動交易觸發**
- **W5 錢包集成**: 使用 24 字助記詞生成錢包
- **私鑰簽名**: 無需 tonkeeper 手動確認，完全自動化
- **Gas 費管理**: 自動配置 0.1 TON 交易費用
- **交易追蹤**: 監控交易狀態直到確認完成

#### ✅ **保障機制**
- **重試邏輯**: 交易失敗時最多重試 3 次 (指數退避)
- **餘額監控**: 自動檢查錢包餘額，不足時暫停服務
- **錯誤恢復**: 網路中斷或 API 異常時自動重連
- **健康檢查**: 系統狀態監控和告警機制

### 🎯 **設計原則**

#### **最小化干預**
- 後端不處理抽獎邏輯，完全依賴智能合約
- 不存儲用戶數據或抽獎結果
- 僅作為自動化觸發器角色

#### **高可靠性**
- 無狀態設計，支持水平擴展
- 優雅關閉和重啟機制
- 詳細日誌記錄和錯誤追蹤

#### **安全性優先**
- 私鑰環境變數管理，不硬編碼
- 最小權限原則，僅執行 `drawWinner`
- 交易參數驗證和安全檢查
